# Browser graphics and pose tools

The Catalog now includes three additional browser workflows. All downloads go into the connected workspace; model and engine files are not shipped with GitHub Pages. Every asset has a pinned size and SHA-256, and its license is downloaded before executable code or weights.

| Catalog item | Engine | Workspace output | Scope |
| --- | --- | --- | --- |
| VTracer | VTracer WebAssembly | `media/vectors/*.svg` | Converts a raster image into editable SVG paths. This is a tracing tool, not a generative AI model. |
| Pose Landmarker Full | MediaPipe Vision | `media/poses/*.json` | Saves 33 normalized and 33 estimated world landmarks for each detected person. A video is sampled at 2 frames per second, up to 90 frames. |
| TripoSR Q8 | ONNX image engine | `media/meshes/*.ply`, `media/meshes/*.glb` | Reconstructs a static colored mesh from a cutout image. It does not create a skeleton or animation. |

Use **Catalog** to download, then **Local Models → Inspect features** to provide an image or video. **Engines** lists VTracer, MediaPipe Vision, and the shared ONNX image engine. The inspector saves a JSON report beside its catalog entry. No model or engine runs until its saved license and binaries pass verification.

TripoSR accepts PNG, WebP, and JPEG, including opaque images with a plain background. **Remove solid background** removes an edge-connected area close to the corner color; adjust **Color tolerance** if the input preview retains a halo or loses part of the object. This simple color removal cannot separate a subject from a similarly colored or busy background. Choose **Clip object manually** in that case, drag the polygon points around the subject, click an edge to add a point, or select and remove a point. **Keep original background** sends the full image through; it works best when the image was already prepared with a gray background and a centered subject. **Object margin** controls the subject's size in the 512 × 512 input. The preview shows the exact gray-composited image sent to the model. These options follow the original [TripoSR preprocessing guidance](https://github.com/VAST-AI-Research/TripoSR/blob/main/gradio_app.py); the browser uses the [ONNX export](https://huggingface.co/cgb/triposr-onnx-webgpu). It uses WebGPU and can require considerably more GPU memory than its approximately 484 MB of downloaded weights. Mesh detail defaults to a 64³ sample grid and can be raised to 128³, with much longer runtimes at higher settings. **Surface threshold** changes where the mesh surface is extracted from the predicted density; it cannot recover details missing from the prediction. Generated meshes include smooth density-gradient normals. The Three.js viewer supports rotation, zoom, pan, a wireframe view, and camera reset. The inspector saves both PLY and GLB; it can also open an existing PLY and save it as GLB without rerunning the model. Both formats keep TripoSR's vertex colors. GLB supports UVs and image textures as a format, but this TripoSR model does not produce either, so neither is invented during export. Its hidden side is an estimate from a single view.

VTracer uses [the published npm WebAssembly build](https://www.npmjs.com/package/@visioncortex/vtracer/v/1.0.0-alpha.4), saved in `engines/VTracer-1.0.0-alpha.4/` with its [MIT license](https://github.com/visioncortex/vtracer/blob/master/LICENSE). The browser adapts its Node loader to compile the saved WASM bytes on demand. Its source image is resized to at most 1024 pixels on the long side before tracing.

Pose Landmarker uses [Google's versioned Full task bundle](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker) and the pinned [MediaPipe Vision npm runtime](https://www.npmjs.com/package/@mediapipe/tasks-vision/v/1.1.1), with Apache 2.0 terms saved in both folders. Google states that image and video input is processed on device; its [privacy notice](https://developers.google.com/edge/mediapipe/solutions/tasks#mediapipe_tasks_privacy_notice) describes MediaPipe usage metrics. The saved JSON contains frame timestamps and both coordinate systems, ready for later skeleton drawing, smoothing, and rig retargeting.

Pose Landmarker detects existing body positions in a photo or sampled video. This is detection and tracking, not pose or motion generation. A single photo provides one observed view; landmarks behind the person and any future movement are estimates or unknown. The saved points do not include a rig, animation, or a verified body shape.

The TripoSR export is [derived from MIT-licensed TripoSR](https://github.com/VAST-AI-Research/TripoSR) and includes an [Apache 2.0 DINO encoder](https://github.com/facebookresearch/dino). Both license texts and the export's model card are saved beside the ONNX files before the weights are downloaded.
