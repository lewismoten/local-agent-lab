# Privacy and hosting

Back to [Local Agent Lab](../README.md) · [Getting started](getting-started.md) · [Workspace guide](workspace.md)

Browser model inference and project file tools run locally. API profiles contact their configured service only when you select and use them; if an API model calls a file, history, or memory tool, its result is sent back to that service so the model can continue. Use a browser model or local Ollama server when project excerpts must stay on your machine. The app does not bundle model weights or third-party engines. The optional catalog downloads pinned upstream assets and saves their license and notice files beside them. Keep those files together when carrying the workspace between machines. For text requests, Wllama is asked to reuse a matching prompt prefix while its model stays loaded; chat and diagnostics show cached prompt tokens when the runtime reports them. This runtime cache is cleared when the model is unloaded and is not written to the portable workspace.

The published app shell is cached in the browser after the first online visit, including its lazy-loaded screens, so it can reopen without a network connection. The first visit reloads once after the service worker takes control so browser engines can use cross-origin isolation on GitHub Pages. This cache belongs to that browser; on a new machine, visit the site once while online. Models, engines, and workspace files remain separate from the site cache and can travel on the chosen drive.

For a public computer, connect the USB workspace through the browser's folder picker. Use **Leave this computer** when finished: after confirmation, it stops this app's downloads, unloads browser models, and clears this app's browser workspace, downloaded models, remembered drive handle, drafts, IndexedDB records, and offline shell cache. It keeps files on the connected drive and leaves other apps' browser storage alone. Close other tabs of this app first; the cleanup page reports anything it could not remove and offers a retry. Browser history and files downloaded outside the app still need the computer's browser controls. Browser-only storage does not travel with a USB drive. The app does not provide workspace encryption yet, so anyone with access to an unencrypted drive can read its files. API profiles contact external providers; choose a browser model when a project must stay local.

Before leaving a shared computer: save your work, choose **Eject workspace** and wait for it to finish, close other tabs of this app, then choose **Leave this computer** and review its cleanup result. Use the browser's own controls to remove history and outside downloads if needed. Finally eject and remove the physical drive. Keep another copy of important drive files; the app cannot recover a lost or erased drive.

Where a browser supports writable origin private file storage, the browser workspace can also save model files and tool files without a folder picker. This storage stays in that browser and does not travel with a USB drive; connect a drive on a browser with folder access for portability. The app checks actual write and remove operations before offering this storage path.

In a disposable Chrome incognito test, browser workspace files remained available across a reload in the same private session and disappeared after all private windows closed. Do not rely on that behavior in another browser or on a managed public computer without testing it there. Save important work to a portable folder before ending a private session.

USB folder access depends on the browser and that computer's policy. The folder picker generally requires a secure page (HTTPS or localhost) and a direct user action; a site cannot silently reconnect a drive on a different computer. The app remembers a selected handle in that browser's IndexedDB, but the browser may ask for read/write permission again after a reload or a new session. A canceled picker leaves the current workspace connected. A public computer may block the picker or USB writes entirely, and an unplugged, read-only, or renamed drive can stop saves until it is reconnected and selected again. Choose a writable subfolder on the drive if its root is restricted. The model catalog shows whether folder-picker and browser-storage APIs are present, but that check cannot prove the drive is writable; actual writes still need permission.

The [GitHub Pages workflow](../.github/workflows/pages.yml) builds and deploys `dist` on `main` at [lewismoten.github.io/local-agent-lab](https://lewismoten.github.io/local-agent-lab/). The source is at [github.com/lewismoten/local-agent-lab](https://github.com/lewismoten/local-agent-lab). In GitHub repository settings, choose **Pages → Build and deployment → GitHub Actions**. Browser folder access requires HTTPS or localhost. The `.gitignore` excludes local workspace data, engines, and model weights from commits.

The build runs [an artifact audit](../scripts/audit-pages-artifact.mjs) before Pages uploads `dist`. It checks the base path, linked files, complete offline precache, package notice text, and absence of optional model weights and engines. Run `npm run audit:published` after a deployment to check the live URLs and notices. On 2026-10-18, the published Pages worker listed 102 cached files; all returned HTTP 200, its notice index had 178 packages with nonempty license text, and its cache list had no model or engine weights. A fresh Chrome profile gained service-worker control, reloaded offline, and opened Models, Files & tools, Journal, and Identities with the network disabled. Run [the offline smoke script](../scripts/check-published-offline.mjs) in a fresh Chrome profile on a debugging port to repeat that check. The current local production preview repeated the offline test with 107 cached files and the same four screens. The deployed build predates Achievements and other current local changes. A physical second-machine model test and optional upstream license review remain; see [model license handling](model-licenses.md).
