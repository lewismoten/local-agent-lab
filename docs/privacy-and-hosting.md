# Privacy and hosting

Back to [Local Agent Lab](../README.md) · [Getting started](getting-started.md) · [Workspace guide](workspace.md)

Browser model inference and project file tools run locally. API profiles contact their configured service only when you select and use them; if an API model calls a file, history, or memory tool, its result is sent back to that service so the model can continue. Use a browser model or local Ollama server when project excerpts must stay on your machine. The app does not bundle model weights or third-party engines. The optional catalog downloads pinned upstream assets and saves their license and notice files beside them. Keep those files together when carrying the workspace between machines. For text requests, Wllama is asked to reuse a matching prompt prefix while its model stays loaded; chat and diagnostics show cached prompt tokens when the runtime reports them. This runtime cache is cleared when the model is unloaded and is not written to the portable workspace.

The published app shell is cached in the browser after the first online visit, including its lazy-loaded screens, so it can reopen without a network connection. The first visit reloads once after the service worker takes control so browser engines can use cross-origin isolation on GitHub Pages. This cache belongs to that browser; on a new machine, visit the site once while online. Models, engines, and workspace files remain separate from the site cache and can travel on the chosen drive.

For a public computer, connect the USB workspace through the browser's folder picker and use **Eject workspace** before removing the drive. The folder travels with you; the app shell cache, browser workspace data, remembered folder permissions, and browser history belong to that computer. Browser-only storage is convenient for a personal device but does not travel with a USB drive. Use the computer's sign-out or browsing-data controls when your session ends, subject to that computer's policies. The app does not provide workspace encryption yet, so anyone with access to an unencrypted drive can read its files. API profiles contact external providers; choose a browser model when a project must stay local.

Where a browser supports writable origin private file storage, the browser workspace can also save model files and tool files without a folder picker. This storage stays in that browser and does not travel with a USB drive; connect a drive on a browser with folder access for portability. The app checks actual write and remove operations before offering this storage path.

The [GitHub Pages workflow](../.github/workflows/pages.yml) builds and deploys `dist` on `main` at [lewismoten.github.io/local-agent-lab](https://lewismoten.github.io/local-agent-lab/). The source is at [github.com/lewismoten/local-agent-lab](https://github.com/lewismoten/local-agent-lab). In GitHub repository settings, choose **Pages → Build and deployment → GitHub Actions**. Browser folder access requires HTTPS or localhost. The `.gitignore` excludes local workspace data, engines, and model weights from commits.

The build runs [an artifact audit](../scripts/audit-pages-artifact.mjs) before Pages uploads `dist`. It checks the base path, linked files, complete offline precache, package notice text, and absence of optional model weights and engines. Run `npm run audit:published` after a deployment to check the live URLs and notices. On 2026-10-18, the published Pages worker listed 102 cached files; all returned HTTP 200, its notice index had 178 packages with nonempty license text, and its cache list had no model or engine weights. A fresh Chrome profile gained service-worker control, reloaded offline, and opened Models, Files & tools, Journal, and Identities with the network disabled. Run [the offline smoke script](../scripts/check-published-offline.mjs) in a fresh Chrome profile on a debugging port to repeat that check. The deployed build predates Achievements and other current local changes. A physical second-machine model test and optional upstream license review remain; see [model license handling](model-licenses.md).
